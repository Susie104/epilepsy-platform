## 0. 一页速览（给决策者）

**要解决的问题**：现有原型跑在教学合成数据上（R² 偏高），真实落地必须换成医院真实队列；而医院真实数据不得提供给课题组、不得离开医院控制范围。

**解决方案一句话**：课题组交付**固定版本的软件 + 模型 + 契约**到医院内网，医院人员自助导入 CSV、自助运行、自助导出；原始数据、明文中间态、结果、密钥、日志**全部留在院内**；课题组**不持有**生产数据、生产账号或任何解密密钥。

**三条通道（默认只开通道 1）**：

| 通道 | 数据流向 | 默认状态 | 适用场景 |
|---|---|---|---|
| **通道 1 · 院内私有化** | 数据不出院，模型下发到院内运行 | **默认开启** | 真实队列验证、批量预测、日常运行 |
| **通道 2 · 院内双层加密接口** | 院内"用户↔平台""平台↔模型服务"两道加密边界，仍在院内 | 可选开启 | 医院合规要求"数据即使在内网也不以明文跨机传输" |
| **通道 3 · 单向模型/统计分发** | **仅**模型权重或差分隐私聚合统计单向流动，**永不回传病例数据** | 需另行批准 | 模型更新、多中心汇总研究 |

**「两次 API 加密」怎么落地**：见 [§3](#3-两次-api-加密的正式解释与实现规格)。默认采用"两道受保护接口边界 + TLS/mTLS"；若医院坚持应用层再加密一次，给出 X25519 + AES-256-GCM + Ed25519 签名 + 防重放的完整信封加密规格，密钥由医院托管。**建议先按 §2 的 D1 拍板，再冻结契约。**

**必须先拍板的 3 件事**：① 加密方案选 A/B/C（§3）；② CSV 是否纳入减药强度字段（§6.3，直接影响模型能否重训）；③ 逆向设计路径是否在首版开放（§6.2，未验证前不得用于临床）。

**最容易被忽略的硬约束**：预测 CSV **不能**自动拿去重训，也**不能**只用预测结果算 R² 或宣称模型性能（§11）。任何对外性能数字必须来自经批准的验证队列。

## 1. 目标、前提与不做清单

### 1.1 目标

院内授权人员可在院内页面完成：**导入 → 预检 → 映射 → 人工确认 → 批量运行 → 查看结果 → 受控导出**，全流程不依赖课题组网络、账号或密钥。

### 1.2 前提

1. 现有模型基于教学合成数据训练，**R² 高不等于真实数据可用**。真实数据接入顺序必须是：授权 → 数据审计 → 模型重训或适配 → 独立验证 → 临床表述审核。
2. 医院提供：服务器或获批的院内计算环境、内网域名与证书、统一身份认证、存储与备份、密钥管理、网络策略、审计平台。
3. 课题组提供：**版本固定**的软件、模型包、CSV 契约、API 契约、部署说明、SHA-256 校验清单、回滚包、合成数据测试集。
4. 研究验证期间任何页面都不得呈现为临床决策结果。

### 1.3 不做清单（明确排除项）

| 不做 | 原因 |
|---|---|
| 不接收医院生产数据到课题组服务器 | 数据责任边界，医院数据不出院 |
| 不由课题组持有生产密钥、生产账号、解密能力 | 密钥托管权必须在医院 |
| 不做公网 URL / 网盘链接抓取 | SSRF 与不可控数据源风险 |
| 不让网页读取服务器本机路径（`C:\...`） | 浏览器无此权限；需信息科配置受限目录连接器 |
| 不自动把预测 CSV 用于重训 | 数据用途未经批准，且会污染验证 |
| 不用预测结果自算 R²/宣称性能 | 性能须来自经批准的验证队列 |
| 不接入外部 LLM / 遥测 / 错误上报 / 公共对象存储 | 生产环境零外部出站 |
| 未验证前不开放逆向设计到临床工作流 | 逆向外推风险显著高于正向预测 |

## 2. 待拍板决策点清单

每条给出**推荐默认值**，评审会只需逐条确认或改选即可，避免开放式讨论拖延契约冻结。

| 编号 | 决策内容 | 可选项 | **推荐** | 影响 |
|---|---|---|---|---|
| **D1** | 「两次 API 加密」采用哪种实现 | A：两道受保护边界 + TLS/mTLS<br>B：A 之上叠加应用层信封加密<br>C：B + 通道 3 单向模型分发 | **A（默认）；若医院合规明确要求则 B** | 决定 §3、§9 的密钥体系与联调工作量 |
| **D2** | 批量预测 CSV 是否纳入减药强度字段 | 是（含 `relative_dose_reduction_pct` 等）<br>否（沿用 v1 八字段） | **是，作为可选列先入库、待算法确认是否进模型** | 直接影响模型能否有效重训；漏掉将导致关键预测因子缺失 |
| **D3** | 逆向设计路径首版是否开放 | 开放（带研究限制水印）<br>暂不开放 | **开放但仅限研究使用，页面显式禁用临床解读** | 需额外 CSV 契约（§6.2）与额外关口 |
| **D4** | 链接入口是否保留 | 保留（受限内网 HTTPS 白名单）<br>只做拖入上传 | **保留，但白名单默认空，由信息科逐个添加** | 影响 SSRF 控制面与联调项 |
| **D5** | 未知值处理策略 | 模型支持三值（1/0/未知）<br>字段不全即拒绝 | **按锁定后的模型契约确定；契约冻结前一律拒绝并提示** | 决定能否处理真实世界不完整病历 |
| **D6** | 患者级分组标识口径 | 单中心 patient_id<br>多中心 site_id + patient_id | **单中心首版用 `case_id`；预留 `site_id` 列** | 影响验证集拆分与未来多中心 |
| **D7** | 部署形态 | Docker 离线镜像<br>Windows 服务（院内 PowerShell 场景）<br>虚拟机 + systemd | **优先 Docker；若院内无容器平台则 Windows 服务** | 决定打包与运维手册形态 |
| **D8** | 结果导出范围 | 院内目录（默认）<br>可导出到院外（禁止） | **仅院内受控目录 + 审计留痕** | 数据出域的唯一出口，必须收口 |
| **D9** | 数据保留期限 | 由医院数据管理制度定，平台侧可配 `retention_days` | **默认 180 天，到期自动清理并留销毁记录** | 影响存储与合规审计 |
| **D10** | 远程运维是否允许 | 不允许<br>医院审批 + 限时段 + 限权限 + 全程录屏留痕 | **原则上不允许；必要时按第二种执行** | 决定是否需要堡垒机/会话审计 |

## 3. 「两次 API 加密」的正式解释与实现规格

### 3.1 先把录音里的表述翻译成技术含义

录音原话有两个关键片段，v1 草案判定为"技术规格不明确"。逐句对照后，最贴合的技术映射如下——**这一段可以直接拿去回答尹老师**：

| 录音原话 | 技术含义 |
|---|---|
| "一个提供我们的 API" | 院内平台对**院内用户/院内系统**提供一组受保护的 `/api/v1/*` 接口（导入、预检、确认、运行、结果、导出） |
| "一个不提供 API，让医院那边自己去接" | 推理接口 `/internal/v1/infer-batch` **不对外暴露、不发给任何人**，只接受院内平台的服务身份；医院信息科自己在院内把它接到平台后面（同机进程内调用或内网 mTLS） |
| "做一个 API 加密" | 两道边界各自的传输加密与身份鉴权：对外 HTTPS + 医院统一身份认证；对内 内网 TLS + 双向证书 + 服务账号 + 固定 schema |
| "医院的真实数据不能提供给我们" | 靠**部署边界 + 密钥托管权**实现，不是靠加密实现（见 §3.6 误区 1） |

因此本方案把"两次 API 加密"定义为**两道受保护的接口边界**，而非"同一份数据加密两次"。若尹老师所指为应用层再加密，则启用 §3.3 的方案 B，规格已写好，可直接实施。

### 3.2 方案 A（推荐默认）：两道受保护接口边界

```text
① 边界一：院内用户 ──HTTPS/TLS 1.2+ ──> 院内反向代理 / API 网关
          鉴权：医院统一身份认证（SSO/OIDC/CAS）
          授权：导入 / 审核 / 运行 / 查看 / 导出 / 管理 六角色
                + 按批次、按对象的权限检查（不只判"是否登录"）
          暴露面：仅医院内网 HTTPS 入口；FastAPI 原始端口不对浏览器开放

② 边界二：院内平台 ──mTLS / 内网 TLS 或同机回环──> 院内模型服务
          鉴权：服务账号 + 双向证书（跨主机）/ 进程内调用（同机）
          授权：仅接受固定 schema 的 infer-batch；拒绝任何浏览器直连
          暴露面：模型端口不进公网、不进院内用户网段，防火墙白名单限定平台主机
```

**要点**：HTTPS/TLS 同时保护请求与响应，已提供机密性、完整性与身份认证。**不自行发明"二次 AES 包装"来替代认证与授权**——鉴权缺失时，加密只会掩盖越权。

### 3.3 方案 B（可选叠加）：应用层信封加密

**启用条件**：医院合规明确要求"数据即使在院内跨机传输、经过反向代理/WAF 解密再加密，也必须保持密文"，或要求平台进程内存之外任何位置都不出现明文。

**算法选型**：

| 用途 | 算法 | 说明 |
|---|---|---|
| 密钥协商 | X25519（ECDH） | 每次请求生成一次性临时密钥对，提供**前向保密** |
| 密钥派生 | HKDF-SHA256 | 输入：共享密钥 + `info="epilepsy-infer-v1"` + salt=`nonce` |
| 载荷加密 | AES-256-GCM | 96-bit 随机 IV，认证标签 128-bit；**禁止**在 GCM 之外另发未认证数据 |
| 报文签名 | Ed25519 | 对规范化后的 header + ciphertext 签名，防篡改与伪装来源 |
| 防重放 | `nonce`(16B) + `timestamp` | 服务端校验时间窗 ±300s，并维护 nonce 缓存（TTL ≥ 时间窗）拒绝重复 |
| 密钥指纹 | SHA-256 前 8 字节 | 写入审计日志，便于回溯使用了哪把密钥 |

**密钥归属（红线）**：医院持有全部私钥（平台服务私钥、模型服务私钥、根签发私钥），托管于院内 KMS/HSM 或受限密钥目录，**双人控制**；课题组**不生成、不保管、不备份**任何医院私钥，只在交付包内提供公钥配置模板与密钥生成脚本供医院自行执行。

**请求报文结构**：

```json
{
  "v": 1,
  "alg": "X25519+HKDF-SHA256+AES-256-GCM",
  "sig_alg": "Ed25519",
  "kid": "hosp-key-2026-11",
  "sender_pub": "base64(临时 X25519 公钥)",
  "nonce": "base64(16 字节随机)",
  "timestamp": 1793990400,
  "ciphertext": "base64(AES-256-GCM(明文业务报文))",
  "tag": "base64(GCM 认证标签)",
  "signature": "base64(Ed25519(canonical(v|alg|kid|sender_pub|nonce|timestamp|ciphertext|tag)))"
}
```

**明文业务报文**（`ciphertext` 解密后即 §8.2 的 `infer-batch` 固定 schema）：`{batch_id, schema_version, model_version, rows[]}`。

**代价与收益（评审时须如实告知医院）**：

- 收益：纵深防御——即使院内某处 TLS 被卸载（反向代理解密检测），报文仍为密文；可对每批数据绑定可追溯的密钥指纹。
- 代价：调试难度显著上升；需医院自建密钥轮换/吊销流程；排错时无法通过常规 TLS 抓包定位问题；性能与联调成本增加。
- 结论：**A 已满足"数据不出院"的核心诉求；B 是合规加分项，不是安全前提。**

### 3.4 方案 C（通道 3）：单向模型 / 统计分发

用于模型更新或多中心汇总研究，**与数据回传无关**：

| 方向 | 允许流动的内容 | 禁止流动的内容 |
|---|---|---|
| 课题组 → 医院 | 签名模型包（Ed25519 签名 + SHA-256 清单 + 变更记录），经离线介质导入并由医院校验后安装 | 任何可执行远程回连的组件、遥测探针 |
| 医院 → 课题组 | ①**无**（默认）；②经医院逐次批准的差分隐私聚合统计（ε 预算由医院确定）；③不含个案的模型运行异常计数 | 原始病例、去标识化后仍可能重识别的字段组合（如罕见综合征 + 精确年龄 + 精确日期）、自由文本、可反推个案的汇总 |

**明确声明**：通道 3 不改变数据责任归属——即便只传聚合统计，仍须经医院数据管理部门逐次书面批准，并记录 ε 预算与批准号。

### 3.5 三方案对比

| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 数据是否出院 | 否 | 否 | 否（仅模型/统计单向） |
| 课题组是否持密钥 | 否 | 否 | 否 |
| 防护范围 | 传输 + 身份 | 传输 + 身份 + 边界内载荷 | 发布完整性 + 汇总研究可行性 |
| 实施复杂度 | 低 | 中-高 | 中 |
| 联调难度 | 低 | 高（无法常规抓包） | 中 |
| **是否默认启用** | **是** | 否（D1=B 时启用） | 否（需单独批准） |

### 3.6 必须澄清的三个误区

1. **「加密 API」≠「数据可以给课题组」**。加密只解决传输与存储机密性；数据不给课题组是靠①软件与模型下发到医院内网运行②密钥与管理员权限在医院③生产环境零外部出站三条边界共同实现的。任何"我们加密后你们发给我们分析"的方案都违反本项目前提，不予实施。
2. **「加密两次」≠「安全两倍」**。若身份认证与对象级授权缺失，加密反而使越权行为更难被发现。安全优先级是：**授权 > 认证 > 加密 > 混淆**。
3. **「医院自己接的那套接口不用做安全」**。恰恰相反：`/internal/v1/*` 是模型与数据的最后一道门，必须限定网络位置（不对用户网段开放）、限定调用方（服务身份）、限定输入（固定 schema）、限定输出（逐行状态，不含原始病历回显）。

## 4. 部署形态与数据流（双通道）

### 4.1 院内部署拓扑

```text
   院内浏览器（医院统一身份认证）
        │  HTTPS / TLS 1.2+
        v
┌───────────────────────────────────────────────────────────┐
│  院内反向代理 / API 网关   ← 边界一（对外唯一入口）         │
│   · 仅内网可达，证书由医院 CA 签发                          │
│   · 速率限制、请求体大小限制、SSRF 白名单校验               │
└───────────────────────────────────────────────────────────┘
        │
        v
┌───────────────────────────────────────────────────────────┐
│  院内 FastAPI 平台 + 任务队列                               │
│  ├─ CSV 预检 / 字段映射 / 映射版本管理                      │
│  ├─ 隔离暂存区（随机文件名 + 限权目录 + 到期清理）          │
│  ├─ 审计存储（链式哈希防篡改）                              │
│  ├─ 内网 LLM（可选，仅做字段抽取，不生成概率）              │
│  └─ 结果库 + 院内受控导出目录                               │
└───────────────────────────────────────────────────────────┘
        │  mTLS / 内网 TLS / 同机回环·进程内   ← 边界二
        v
┌───────────────────────────────────────────────────────────┐
│  院内模型服务（推理适配层）                                 │
│   · 端口不进用户网段、不进公网                              │
│   · 模型文件 SHA-256 不符则拒绝启动                         │
│   · 版本锁定，只读挂载                                      │
└───────────────────────────────────────────────────────────┘

  ✗ 禁止出站：外部模型 API / 遥测 / 错误上报 / 公共对象存储 / 课题组服务器
```

### 4.2 部署形态选型（决策点 D7）

| 形态 | 交付物 | 适用条件 | 资源基线 |
|---|---|---|---|
| **Docker 离线镜像（推荐）** | 镜像 tar 包 + `docker load` 脚本 + compose 文件 + SHA-256 清单 | 院内已有容器平台或可装 Docker | 4C / 8GB / 50GB，无 GPU 需求（首版） |
| **Windows 服务** | 离线 wheelhouse + Python 嵌入式运行时 + NSSM/服务注册脚本 + PowerShell 运维命令 | 院内只有 Windows 服务器（与录音中"PowerShell + CSV"的院内使用习惯一致） | 同上 |
| **虚拟机 + systemd** | 离线 Python 环境 + systemd unit + 日志轮转配置 | 院内 Linux 虚拟机、无容器平台 | 同上 |

三种形态共用同一套代码与契约，仅打包与运维脚本不同。**首版建议只做 1 种**，避免三套运维手册。

### 4.3 通道 2 / 通道 3 的数据流（默认关闭）

```text
通道 2（D1=B 时启用）：
  用户 ─HTTPS─> 网关 ─[信封密文]─> 平台 ─[信封密文 + mTLS]─> 模型服务
                 每跳报文均为 AES-256-GCM 密文 + Ed25519 签名 + nonce 防重放
                 密钥全部由医院 KMS 托管，课题组零持有

通道 3（需单独批准）：
  课题组 ──离线介质──> 医院校验(SHA-256 + Ed25519 签名) ──> 院内安装模型包   [单向：模型进院]
  医院 ──逐次批准──> 差分隐私聚合统计(ε 由医院定) ──> 课题组                  [单向：统计出院，禁止个案]
```

### 4.4 基础设施与安全责任划分

- **医院提供并掌握**：服务器/计算环境、内网域名、证书与院内 CA、统一身份认证、存储与备份、密钥管理（KMS/HSM 或受限目录）、出站网络策略、审计平台、系统管理员权限、数据保留与销毁制度。
- **课题组提供**：版本固定的软件与模型、契约文档、部署说明、SHA-256 清单与回滚包、合成数据测试集、故障复现指引（基于合成样例）。
- **红线**：生产数据库、模型服务、LLM 均不部署在课题组控制的服务器；课题组不取得医院生产数据、生产账号、解密密钥；远程运维按 D10 执行。

### 5.1 页面骨架

```text

数据来源
┌ 拖入 CSV / 点击选择文件 ─────────┐  ┌ 粘贴医院内网文件链接 ──────────────┐

└──────────────────────────────────┘  └────────────────────────────────────┘

研究路径： ○ 正向预测   ○ 逆向设计（研究使用，未通过验证前不可作临床解读）

① 预检  识别编码 / 列名 / 行数 / 缺失与冲突 / 日期 / 重复 / 不合法值
② 映射  医院列名 → 标准字段；显示映射规则、映射版本号、抽样预览（脱敏后）
③ 确认  审核人确认用途、索引时间规则、映射版本、schema 版本、模型版本

⑤ 结果  分页查看 / 院内受控导出 / 审计留痕
```

### 5.2 与现有前端的关系

新增的「**导入自己的数据**」作为第三条入口，与现有「正向预测 ↗」「逆向设计 ↗」并列（即截图红笔所指位置）。三者共用同一套深色视觉语言与组件：

| 入口 | 数据来源 | 面向对象 |
|---|---|---|
| 正向预测 | 内置教学合成数据 | 演示 / 教学 |
| 逆向设计 | 内置教学合成数据 | 演示 / 教学 |
| **导入自己的数据（新增）** | **医院真实 CSV（院内，不出院）** | 院内研究与验证 |

新入口页面必须常驻显示：`教学/研究联调，不用于临床决策`、当前 `schema_version · model_version · mapping_version`、数据留存倒计时。

### 5.3 链接入口的限制（决策点 D4）

- 首版**只接受医院审批通过的内网 HTTPS 文件服务域名**，白名单默认空，由信息科逐个添加。
- 由院内平台**服务端**使用专用服务身份读取；不接受任意公网 URL、URL 内嵌用户名/密码、重定向到外网、未批准网盘、内网管理地址、云元数据地址（`169.254.169.254` 等）→ 防 SSRF。
- 限制目标解析地址（禁私网/回环越界）、文件大小、下载超时；下载后走与拖入文件**完全相同**的预检链。
- 粘贴本机路径（`C:\…`、`D:\…`）**不等于**浏览器获得读取权限：本机文件请走拖入/选择；院内共享目录须由信息科配置**受限目录连接器**，不允许网页任意读取服务器路径。
- 后续如需对接 HIS / 数据平台，另建专用接口，不复用通用 URL 抓取。

### 5.4 页面上绝不出现的元素

外部 LLM 上传入口、公开网盘、课题组服务器地址、"把数据发送给研发团队排错"类按钮、任何遥测开关、导出到院外目录的选项。

## 6. CSV 契约与预检规则

### 6.0 字段计数口径（澄清 v1 的表述歧义）

v1 表述为"八个模型字段"，但其表格共 10 行。统一口径：**批量预测文件 = 2 个管理字段 + 8 个模型字段 = 10 列**。管理字段（`case_id`、`index_date`）不进入模型特征矩阵，仅用于批次追踪与随访窗口计算。下文一律按此口径表述。

### 6.1 批量预测文件（正向预测）

一行代表一个待预测的索引事件。`case_id` 为**院内生成的不可逆代号**，不得使用姓名、身份证号、手机号、住院号明文（生成规则见 §9.1）。

| # | 列名 | 类型 | 含义 | 校验规则 |
|---|---|---|---|---|
| M1 | `case_id` | 管理 | 院内病例代号 | 必填；同批次唯一；生成规则见 §9.1；禁止直接标识符 |
| M2 | `index_date` | 管理 | 首次实际减药日期 | 必填；`YYYY-MM-DD`；由病历与审核人确定；不得晚于当前日期 |
| F1 | `epilepsy_duration_before_remission_years` | 模型 | 缓解前病程（年） | 非负有限数；建议上限 100；未知留空 |
| F2 | `seizure_free_months` | 模型 | 减药前无发作月数 | 非负有限数；建议上限 600；未知留空 |
| F3 | `age_at_onset` | 模型 | 起病年龄（年） | 非负有限数；建议上限 120；未知留空 |
| F4 | `febrile_seizure_history` | 模型 | **患者本人**热性惊厥史 | `1`/`0`/空；**未提及不得填 0**；家族史不计入本字段 |
| F5 | `seizure_count_before_remission` | 模型 | 缓解前发作次数 | 非负整数；建议上限 10000；未知留空 |
| F6 | `self_limiting_syndrome` | 模型 | 自限性癫痫综合征 | `1`/`0`/空；综合征名称需在映射表登记 |
| F7 | `developmental_delay` | 模型 | 发育迟缓 | `1`/`0`/空 |
| F8 | `eeg_epileptiform` | 模型 | EEG 癫痫样异常 | `1`/`0`/空；**普通非特异性异常不得自动等同为 1** |

> 表中标注"建议上限"的数值为默认护栏，**必须由临床负责人在契约冻结前书面确认**（§16 Q1）。三值字段（`1`/`0`/空）的模型处理方式由决策点 D5 确定；契约冻结前一律按"空即拒绝"处理，并在结果中给出拒绝码。

### 6.2 逆向设计文件（新增，决策点 D3）

逆向设计的路径是"给定目标风险 → 反推可行的减药幅度"，其输入契约与正向预测**不同**：除 §6.1 的 10 列外，还需减药强度相关字段。v1 缺少这部分，导致逆向设计无法用真实数据驱动。

| # | 列名 | 类型 | 含义 | 校验规则 |
|---|---|---|---|---|
| B1 | `asm_name` | 必填 | 抗发作药物名称（减药的目标药物） | 需在院内药物字典中可映射；自由文本须登记映射 |
| B2 | `current_daily_dose_mg` | 必填 | 减药前当前日剂量（mg） | > 0 有限数；单位统一为 mg，µg/g 须在映射表换算 |
| B3 | `planned_reduction_pct` | 必填 | 计划减药幅度（%，0–100） | 有限数；0 ≤ x ≤ 100；支持多行扫描式输入 |
| B4 | `reduction_schedule` | 必填 | 减量方式 | 枚举：`single_step` / `stepwise`；自由文本须登记映射 |
| B5 | `reduction_steps` | 条件必填 | 分次减量的步数与间隔（周） | 当 B4=`stepwise` 时必填；整数 > 0 |
| B6 | `asm_polytherapy` | 选填 | 是否联合用药 | `1`/`0`/空 |
| B7 | `previous_reduction_failure` | 选填 | 既往减药失败/复发史 | `1`/`0`/空 |

**逆向设计的强制约束**：

1. 未经院内独立验证前，逆向设计输出**仅显示为研究用探索结果**，页面与导出文件均带 `RESEARCH_ONLY — 不可用于临床决策` 标识。
2. 逆向外推超出训练支持范围时必须拒绝，返回 `E403`（见 §7.2），**不得**用模型外插值填充。
3. 禁止输出"处方建议"式表述（如"建议减至 X mg"）；合规表述上限为"在给定支持范围内，目标风险 ≤ Y% 对应的减药幅度区间为 [a, b]"。
4. B1/B2 的真实用药数据属于高敏字段，导出与日志脱敏等级高于预测结果（§9.1）。

### 6.3 候选扩展字段（决策点 D2，需算法负责人确认）

场景为"减药后复发"，但 v1 的 8 个模型字段中**没有任何减药强度变量**。这在建模上是实质性缺口：减药幅度与减药方式通常是复发风险的重要预测因子，若契约中不采集，真实队列重训时无法评估。建议至少将下列字段作为**可选列**先落地入库（先采、后定是否进模型）：

| 列名 | 含义 | 建议理由 |
|---|---|---|
| `relative_dose_reduction_pct` | 实际减药幅度（%） | 与场景定义直接相关，极可能为主预测因子 |
| `reduction_strategy` | 减量方式（单次/分次） | 影响风险的时间分布 |
| `asm_count` | 减药时用药种数（单药/多药） | 常见混杂因素 |
| `previous_asm_failure_count` | 既往发作药物失败次数 | 反映难治程度 |

> 处理方式：契约冻结前由算法负责人确认①是否纳入模型②纳入后的缺失处理策略。**先采集、后建模**的成本远低于回头补采（真实队列回溯采集需重新过伦理与病历调阅）。

### 6.4 验证 / 重训文件必须与预测文件分开

| 用途 | 模板 | 必备额外列 | 权限 |
|---|---|---|---|
| 批量预测 | §6.1（+ §6.2 逆向） | — | 导入员 / 运行员 |
| 模型验证 | 独立模板 | `follow_up_days`、`outcome_event`（1=复发/0=未复发）、`censoring_status`（删失/失访/存活）、`censoring_reason`、`patient_level_group_id` | 验证研究员（单独授权） |
| 模型重训 | 独立模板 | 同上 + `site_id`（多中心预留） | 算法负责人 + 医院双签批准 |

**硬约束**：

1. 平台**不得**把预测用途导入的 CSV 自动用于重训或验证（用途绑定在 `confirm` 步骤，写入审计与元数据）。
2. **不得**只用预测结果计算 R² 或任何临床性能指标。
3. 训练 / 内部验证 / 独立验证使用**不同批次与不同权限组**，患者级拆分（同一患者不得跨集）。
4. 所有性能报告由医院批准后决定是否对外；小样本汇总须评估重识别风险后再发布。

### 6.5 文件格式与上传安全

| 项 | 规则 |
|---|---|
| 编码 | UTF-8（可识别 UTF-8 BOM）；GBK/GB18030 由院内配置显式声明后转码，不做静默猜测 |
| 上限 | 文件大小、行数、列数、单字段长度、总任务时长均为院内可配置项（默认建议：50MB / 10 万行 / 200 列 / 4096 字符 / 单任务 30 分钟） |
| 暂存 | 上传先落院内隔离暂存区：随机文件名、限权目录（仅服务账号可读写）、禁执行位 |
| 解析 | 先扫描/校验后才解析；**不执行 CSV 单元格内容**；防公式注入（导出时以 `'` / Tab 前缀转义 `=`、`+`、`-`、`@` 起始单元格） |
| 清理 | 未确认文件按 `retention_days` 自动清理；预检失败文件保留错误报告，不保留正文 |
| 日志 | 逐行错误报告含**行号 + 字段名 + 错误码**，**不返回整行病历内容**到普通日志 |
| 参考 | [OWASP 文件上传安全指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) |

### 6.6 字段映射与单位换算

1. 医院表头与标准字段不同时，由**审核人**建立"医院列名 → 标准字段"映射，映射保存为**带版本号**的可复用配置（`mapping_version`），并在 `confirm` 步骤锁定。
2. 单位换算（mg↔µg、月↔年、次↔频次区间）、空值语义、重复事件去重规则、索引时间判定规则**必须显式记录**在映射版本中，可追溯、可复现。
3. **不得把空值自动改为 0**；不得把"未提及"当作"阴性"。
4. 8 个模型字段不全、证据冲突、或未审核的行进入"待复核 / 拒绝"列表，**不返回默认概率**。
5. 模型是否允许部分缺失及其支持范围，以**锁定后的真实数据模型契约**为准（决策点 D5）。

### 7.3 拒绝码表（固定错误分类，便于统计与临床沟通）

| `E202` | 模型字段类型非法（文本写入数值列） | 拒绝该行 |
| `E203` | 三值字段出现非法枚举（如 `2`/`Y`） | 拒绝该行 |

| `E402` | 模型文件 SHA-256 校验失败 | 拒绝启动/运行 |
| `E403` | 逆向设计外推超出可行域 | 拒绝该行，不输出数值 |
| `E501` | 文件超限（大小/行数/列数/字段长度） | 整批拒绝 |
| `E502` | 编码不可识别 | 整批拒绝 |
| `E503` | 链接来源不在白名单 / 疑似 SSRF | 整批拒绝并记安全审计 |
| `E601` | 越权访问（对象级权限不足） | 拒绝并记安全审计 |

## 8. API 设计

### 8.1 对外接口 `/api/v1`（边界一）

仅供**医院院内用户或获批的院内系统**调用。所有带 ID 的操作都必须按 `用户 × 科室/项目 × 数据批次 × 对象` 做**对象级权限检查**；只判"是否登录"不构成授权。参考 [OWASP API 安全风险](https://api-security.owasp.org/editions/2023/en/0x11-t10/)。

| API | 调用方 | 输入 / 返回 | 最低权限 |
|---|---|---|---|
| `POST /api/v1/imports/file` | 拖入入口 | `multipart/form-data` CSV + `purpose`(`prediction`/`reverse`/`validation`/`retrain`)；返回 `import_id`、文件 SHA-256、预检状态 | 导入员 |
| `POST /api/v1/imports/link` | 链接入口 | `{source_url}`；服务端按白名单获取；返回 `import_id` | 导入员 |
| `GET /api/v1/imports/{id}/validation` | 预检页 | 列清单、可映射性、汇总统计、逐行错误（行号+字段+错误码）、可运行行数 | 同批次授权者 |
| `POST /api/v1/imports/{id}/mappings` | 映射页 | 医院列名 → 标准字段；生成/更新 `mapping_version` | 审核员 |
| `POST /api/v1/imports/{id}/confirm` | 审核页 | `{purpose, mapping_version, index_rule, schema_version, model_version, note}`；审核人身份留痕 | 审核员 |
| `POST /api/v1/runs` | 运行按钮 | `{import_id, scenario(forward/reverse), model_version, options}`；返回 `202` + `run_id`；幂等键 `Idempotency-Key` | 运行员 |
| `GET /api/v1/runs/{id}` | 进度页 | 状态、计数（成功/拒绝/待复核）、版本三元组、错误摘要 | 同批次授权者 |
| `POST /api/v1/runs/{id}/cancel` | 运行页 | 中止任务；已产出部分标记为 `CANCELLED` 并留痕 | 运行员 |
| `GET /api/v1/runs/{id}/results` | 结果页 | 分页结果（§7 schema）、拒绝原因、模型来源/版本、支持范围声明 | 结果查看者 |
| `POST /api/v1/runs/{id}/exports` | 导出按钮 | `{purpose, format(csv/json/xlsx)}`；生成院内受控目录文件 + 审计记录 + 导出人签核 | 导出授权者 |
| `POST /api/v1/predictions` | 单例录入 | 经审核的 8 字段（+逆向字段）；返回单例结果或明确拒绝码 | 单例预测授权者 |
| `GET /api/v1/meta/versions` | 任意页 | `{app_version, schema_version, model_version, model_sha256, signature_valid}` | 已登录院内用户 |
| `GET /healthz` `/readyz` | 运维 | 存活/就绪 + **模型 SHA 校验结果**；不返回业务数据 | 院内监控 |

**通用约定**：

- 任务状态机：`UPLOADED → VALIDATING → NEEDS_REVIEW | READY → QUEUED → RUNNING → COMPLETED | PARTIAL_FAILED | FAILED | CANCELLED`。
- 幂等：`POST /runs` 与 `POST /exports` 必须支持幂等键，避免重复批次与重复导出。
- 错误格式固定：`{code, message, details, request_id}`；**错误体中不得附原始病历、行内容或异常堆栈**。
- 限流：按用户 + IP 维度限速；批量接口设最大并发任务数（默认 4）。

### 8.2 内部推理接口 `/internal/v1`（边界二，不对外）

`POST /internal/v1/infer-batch`：

```json
{
  "batch_id": "b-20261107-01",
  "schema_version": "1.0.0",
  "model_version": "epi-relapse-730d@0.4.1",
  "mapping_version": "hosp-a-map@3",
  "scenario": "forward",
  "rows": [
    {
      "case_id": "0a1b2c3d4e5f6789",
      "index_date": "2026-03-11",
      "features": {"f1": 6.2, "f2": 27, "f3": 9, "f4": 0, "f5": 4, "f6": 0, "f7": 0, "f8": 1}
    }
  ]
}
```

**约束**：仅接受平台服务身份（mTLS 客户端证书 / 同机进程内调用）；**拒绝任何浏览器直连**；拒绝 `schema_version` 与模型不匹配的请求；响应**逐行**返回 `{case_id, status, risk_730d, ci, in_support, reject_codes}`，**不回显原始病历字段**；启用方案 B 时该报文置于 §3.3 的信封结构内传输。

## 9. 脱敏、密钥与审计规范

### 9.1 标识符与脱敏规则

| 项 | 规则 |
|---|---|
| `case_id` 生成 | `HMAC-SHA256(院内病案号, 院内随机盐)` 取前 16 位十六进制；盐与 HMAC 密钥由医院保管，**课题组不可反推**；禁止直接写入病案号、住院号、身份证、手机号、姓名 |
| 禁止字段清单 | 姓名、身份证号、手机号、住址、就诊卡号、床号、影像号、家属信息、可识别的自由文本；预检阶段做**关键词+正则黑名单扫描**，命中即拒绝该列并告警 |
| 日期 | 院内运行使用绝对日期（数据不出院）；若任何产物需出院（通道 3 的聚合统计），一律转为**相对天数**并做日期偏移，偏移量由院内固定盐决定，保证同一患者时间间隔一致 |
| 抽样预览 | 页面预览必须使用**脱敏后**的行，且默认只显示列级统计与前 5 行摘要；预览不出现在普通日志中 |
| 高敏字段 | 逆向设计的 `asm_name` / `current_daily_dose_mg` 采用更高脱敏等级：不进日志、不进错误信息、不进遥测、导出时按角色控制 |
| 导出防注入 | CSV/XLSX 导出对 `= + - @` 起始单元格加前缀转义 |

### 9.2 密钥管理规范

| 环节 | 要求 |
|---|---|
| 生成 | 由医院在院内执行交付包中的密钥生成脚本（X25519 / Ed25519），或从院内 KMS/HSM 签发；课题组**不提供任何预置私钥** |
| 保管 | 私钥存于院内 KMS/HSM 或权限 0600 的受限目录；**密钥与数据分权管理**（不同管理员）；双人控制高权限密钥 |
| 分发 | 只分发公钥与 `kid`；配置模板入代码库，**私钥与生产配置永不入代码库** |
| 轮换 | 默认 12 个月或人员变动、疑似泄露时立即轮换；轮换期支持双 `kid` 并存以平滑过渡 |
| 吊销 | 维护吊销列表（`kid` + 时间 + 原因 + 审批人），服务端拒绝已吊销 `kid` |
| 托管红线 | **禁止**将私钥/口令托管给课题组、写入工单、贴入聊天工具、放入备份到院外的介质 |
| 可追溯 | 审计日志记录 `kid` 与密钥指纹（SHA-256 前 8 字节），**不记录密钥本身** |
| 销毁 | 到期销毁须留操作记录与审批号 |

### 9.3 审计日志 schema

| 字段 | 说明 |
|---|---|
| `event_id` | 事件唯一 ID |
| `ts` | UTC 时间戳（含毫秒） |
| `actor` / `actor_role` | 操作者标识（院内账号哈希）与角色 |
| `action` | `IMPORT_FILE` / `IMPORT_LINK` / `MAP` / `CONFIRM` / `RUN` / `CANCEL` / `VIEW_RESULT` / `EXPORT` / `LOGIN` / `AUTHZ_DENY` / `KEY_ROTATE` 等 |
| `object_type` / `object_id` | `import` / `run` / `mapping` / `export` + ID |
| `batch_id` / `run_id` / `import_id` | 批次追溯三元组 |
| `purpose` | 数据用途（绑定 confirm） |
| `versions` | `{schema_version, model_version, mapping_version}` |
| `result` | `ALLOW` / `DENY` / `FAIL` + 错误码 |
| `client_ip_hash` | 客户端地址哈希（不存明文 IP） |
| `kid` / `key_fingerprint` | 使用密钥标识与指纹 |
| `prev_hash` / `event_hash` | **链式哈希**，防篡改；每日摘要可由医院留存校验 |

**禁止记录**：CSV 正文、病历原文、行级明文、令牌、密钥、密码。关闭外部遥测——测试、备份、故障排查同样适用。

## 10. 安全控制与量化验收指标

### 10.1 安全控制最低要求

| 环节 | 最低要求 |
|---|---|
| 传输 | 用户→网关仅 HTTPS（TLS 1.2+，禁用弱套件与证书校验绕过）；跨主机服务调用使用内网 TLS + 双向认证；方案 B 场景下报文再经信封加密 |
| 身份与权限 | 接医院统一身份认证；六角色（导入/审核/运行/查看/导出/管理）分离；按批次与对象授权；高权限操作经医院审批；**服务账号与人员账号严格分开** |
| 存储 | 原始文件、暂存、结果、备份全部在院内；按医院密码与密钥规范加密；明确保留期限（默认 180 天）、到期清理与销毁记录 |
| 链接读取 | 仅批准的 HTTPS 域名/路径；限制目标解析地址、重定向跳数、文件大小、下载超时；禁止任意 URL、内网管理地址、云元数据地址 |
| 日志与运维 | 见 §9.3；关审计缺失即视为不合规 |
| 发布 | 依赖与模型固定版本；交付 SHA-256 清单、部署说明、变更记录、回滚包；医院审核后离线安装；生产配置与密钥不入代码库 |
| 合规 | 医疗健康信息属敏感个人信息，处理目的、权限、留存须按医院数据使用审批与安全管理制度确定；医疗卫生机构对本单位网络安全负主体责任，收集/传输/存储/使用/销毁全流程管理。参考 [《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)、[《医疗卫生机构网络安全管理办法》](https://app.www.gov.cn/govdata/gov/202208/31/488953/article.html) |
| 伦理 | 真实数据接入前须取得医院伦理批件与数据使用协议（DUA）；批件号记入 `confirm` 元数据 |

### 10.2 量化验收指标（可测、可签字）

**功能与数值**

| 指标 | 目标 |
|---|---|
| 端到端跑通 | 合成 CSV 从导入到院内导出全链路成功，同一文件两次运行产生**相同的文件 SHA-256 与相同结果** |
| 数值复现 | 固定教学病例在锁定版本下复算误差 ≤ 1e-6 |
| 模型完整性 | 模型文件 SHA-256 不符时**拒绝启动/运行**（`E402`），有明确页面提示 |

**拒绝与防护（逐条应被明确拒绝，且拒绝时不得返回默认风险值）**

- 本机路径（`C:\…`）、外网链接、未列入白名单的内网地址、重定向跳转、超限文件、非法列名、重复 `case_id`、缺失/冲突字段。
- 未登录、越权访问他人 `import_id`/`run_id`、无效服务证书、绕过 `confirm` 直接运行、用途不匹配（预测文件用于重训）。

**性能（院内基线，可按硬件调整并记入部署文档）**

| 指标 | 目标 |
|---|---|
| 单批 1,000 行 | 端到端（预检+推理+落库）≤ 60s |
| 单批 10,000 行 | ≤ 5min |
| 并发任务 | ≥ 4 个批量任务并行不互相阻塞 |
| 预检吞吐 | ≥ 10,000 行/分钟 |
| 页面首屏 | ≤ 2s（内网） |

**网络隔离与安全验证**

| 指标 | 目标 |
|---|---|
| 断网演练 | **物理断开医院出站网络后，全流程仍可完整运行** |
| 抓包 | 出站抓包无任何病例明文；无对课题组/公网域名的连接尝试 |
| 日志抽查 | 日志、错误响应、备份、导出目录经医院抽查，均无病历原文与凭证 |
| 渗透项 | 至少覆盖：未授权访问、越权（对象级）、SSRF、文件上传、CSV 注入、限流绕过 |

## 11. 模型与临床使用关口

三道关口**顺序不可跳过**，每道关口都有独立的准出条件与责任人。

| 关口 | 数据 | 准入条件 | 准出条件 | 页面表述 |
|---|---|---|---|---|
| **① 工程阶段** | 仅教学合成数据 | 契约草案确定 | 入口、CSV 校验、接口、权限、离线运行、固定数值复算全部通过 §10.2 验收 | "教学联调，不用于临床决策" |
| **② 院内研究验证阶段** | 医院真实队列 | 伦理批件 + DUA + 数据授权 + 队列审计完成 | 患者级拆分、独立验证、校准、亚组、缺失值分析完成；**模型与阈值锁定**；临床方冻结预测时点、纳排标准、8 字段医学定义与结局定义 | "院内研究验证中，限获批研究人员查看" |
| **③ 临床使用评审阶段** | 锁定后的模型 | 关口②全部通过 | 医院临床/信息/安全/伦理/法规负责人共同确认适用范围、性能、使用说明、人工复核流程与监管属性 | 按批准范围表述 |

关键约束：

1. **不能由"接口已加密"推定可临床使用**。若涉及医疗器械软件管理，由法规团队按实际功能判定。国家药监局正持续研究人工智能医疗器械与医用大模型管理要求：[国家药监局公告](https://www.nmpa.gov.cn/xxgk/ggtg/ylqxggtg/ylqxqtggtg/20250703163951182.html?m=&type=pc)。
2. 关口②之前的任何真实数据结果**不得**用于对外汇报性能、不得写入论文、不得进入临床工作流。
3. 真实队列上 R² / AUC 低于合成数据表现属**预期内的正常现象**，应在验证报告中如实说明，不得通过调阈值或改口径掩盖。

**LLM 使用边界**：若用内网 LLM 从病历抽取 8 字段，必须在医院批准的院内环境运行；保留原文证据与时间戳、逐项人工确认；**LLM 不生成概率、不建议调药、不修改数值**；抽取失败或字段不齐时拒绝推理（不给部分结果）。

## 12. 版本与契约冻结机制

任何一份结果文件都必须能回答"这是哪一版跑出来的"。采用**版本三元组**：

```text
schema_version   CSV 契约版本（列名、类型、允许范围、拒绝码语义）
mapping_version  医院列名映射版本（含单位换算与空值规则）
model_version    模型包版本（含 SHA-256 与 Ed25519 签名）
```

- 三元组写入：确认步骤元数据、每次运行的审计日志、每份导出文件的头部注释/元数据 sheet、结果页页脚。
- 契约变更流程：算法/临床提出变更 → 更新 `schema_version`（语义化版本）→ 同步更新 CSV 模板、JSON Schema、OpenAPI、拒绝码表、示例文件 → 医院信息科与数据责任方评审 → 冻结并归档旧版本。
- **不兼容变更**（改列名、改语义、改单位）必须升 major 版本，旧批次结果须标注为不可比。
- 交付包内容：镜像/安装包、`SHA256SUMS`、模型签名、OpenAPI 文档、JSON Schema、CSV 模板、示例合成数据、部署说明、变更记录、回滚包、验收清单。

## 13. 实施阶段、依赖与交付物

阶段以**依赖关系**排序，不含时间承诺；标注"可并行"的阶段可穿插推进。

| 阶段 | 前置依赖 | 工作内容 | 可验收交付物 |
|---|---|---|---|
| **A. 冻结契约** | 决策点 D1–D10 拍板（§2）、§16 待确认项关闭 | 医院确认部署位置、内网链接白名单、CSV 样本、字段医学定义、角色权限矩阵、留存期、审批范围；算法方锁定模型接口与支持范围声明 | CSV 模板（正向/逆向/验证/重训）、OpenAPI 文档、JSON Schema、权限矩阵、数据流图、模型版本清单、拒绝码表 |
| **B. 做入口（可与 C 并行）** | A | 拖拽上传、链接粘贴（白名单）、预检、字段映射与映射版本、错误报告（按码归类）、人工确认、任务进度与取消、结果页、单例录入、导出与防注入、版本三元组展示 | 用合成 CSV 从入口到导出的端到端演示 + §10.2 功能/拒绝类验收记录 |
| **C. 院内安全部署（可与 B 并行）** | A | 统一身份认证对接、HTTPS/证书、内部服务认证（mTLS）、加密存储、审计日志（链式哈希）、备份与留存清理、出站限制、离线安装与回滚、（D1=B 时）信封加密与密钥体系 | 医院信息科部署手册、运维命令清单、安全验收记录、断网演练记录、抓包报告 |
| **D. 真实数据研究验证** | B + C 完成、伦理批件、DUA、队列审计 | 院内导入真实队列、数据质量审计、患者级拆分、模型重训或适配、独立验证、校准与亚组分析、缺失值分析、阈值锁定、临床文案审核 | 院内验证报告（含性能与限制）、冻结的模型包（含 SHA 与签名）、结果使用边界声明 |
| **E. 决定临床上线** | D + 法规/伦理评审 | 依据验证与评审结论调整功能、告知语、人工复核流程与工作流 | 医院批准的上线范围、运行维护责任书、用户培训记录 |

**交接原则**：各方以**书面交接清单**确定责任；每次交付附 SHA-256 清单与变更记录；医院验收签字后方可进入下一阶段。

## 14. 责任矩阵（RACI）

R=执行 A=批准 C=咨询 I=知情

| 工作项 | 课题组/研发 | 算法负责人 | 临床负责人 | 医院信息科 | 数据责任方 | 伦理/法规 |
