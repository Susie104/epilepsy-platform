## 2. 本地联调（合成数据）

```bash
python3 -m pip install -r requirements.txt
bash run.sh                       # 默认 127.0.0.1:3000，方案 A
```

浏览器打开后：**导入自己的数据** → 「合成演示 CSV（可运行）」→ 保存映射 → 确认 →
开始运行 → 结果 → 导出。角色在顶部身份条切换（演示桩，生产接医院 SSO）：

| 步骤 | 所需角色 |
|---|---|
| 导入 CSV | 导入员 |
| 保存映射 / 确认批次 | 审核员 |
| 开始运行 | 运行员 |
| 查看行级结果 | 结果查看者 |
| 导出 | 导出授权者 |
| 审计与加密自检 | 系统管理 |

> 运行员看不到行级结果（返回 `E601`）是**刻意的角色分离**（方案 §8.1）；
> UI 会给出「切换为结果查看者并加载」的引导。

演示违规样例：点「合成演示 CSV（含违规行）」可看到 `E103`（重复/直接标识符列）、
`E104`（日期非法）、`E201`（越界）、`E202`（类型非法）、`E203`（非法枚举）、
`E204`（必填为空）逐行错误报告——**被拒绝的行不返回默认风险值**。

## 3. 通道 2（边界二信封加密，方案 B）

```bash
python3 -m gateway.keygen --dir var/keys --kid-prefix <医院代号>   # 由医院执行
CHANNEL2=1 bash run.sh                                              # 启用信封加密
```

启用后，边界二不再进程内调用，而是平台 → 模型服务的 HTTP 调用，报文为
AES-256-GCM 密文 + Ed25519 签名 + nonce 防重放，并需服务令牌 `X-Internal-Token`。
在 UI「审计与安全自检」页可一键验证：加密回环、重放拦截、`kid` 与密钥指纹（只显公钥指纹）。

密钥重建：`python -m gateway.keygen --dir var/keys --force` 会覆盖原密钥；当前未实现轮换期双 `kid` 并存，不可据此执行生产密钥轮换。

## 4. 院内正式部署（阶段 C，医院信息科执行）

1. 前置：确认 `D7` 部署形态（Docker / Windows 服务 / 虚拟机 systemd）、服务器规格（基线 4C8G50GB）。
2. 反向代理与证书：只暴露院内 HTTPS 入口；平台端口与模型端口不对浏览器开放。
3. 身份认证：把 `server.py` 的 `actor()` 身份桩替换为医院 SSO/OIDC/CAS；服务账号与人员账号分开。
4. 出站限制：防火墙禁止访问外部模型 API、遥测、公共对象存储、课题组服务器。
5. 离线安装：校验 `SHA256SUMS`（模型包），失败则拒绝启动（`E402`）。
6. 留存与销毁：配置 `retention_days`（默认 180 天），启动时自动清理暂存并留销毁审计。
7. 生产化替换清单（当前 MVP 的已知简化）：
   - Flask 开发服务器 → 生产 WSGI（gunicorn/waitress）+ 反向代理；
   - `var/*.json` 文件存储 → 院内数据库与对象存储（加密落盘）；
   - 后台线程任务队列 → 院内消息队列（带并发上限与重试）；
   - 演示身份桩 → 医院统一身份认证 + 批次级授权（`scope` 已预留）。
